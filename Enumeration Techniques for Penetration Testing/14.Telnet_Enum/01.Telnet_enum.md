## Telnet Service Enumeration & Exploitation Notes## 1. Telnet Service Enumeration
Telnet service enumeration is the process of scanning, identifying, and interacting with an open Telnet port (typically Port 23) to gather system banners, software versions, and configuration details.
## Step 1: Discover Open Telnet Ports
Check if the target has an active Telnet service. While Telnet typically runs on port 23, administrators sometimes move it to non-standard ports (like 2323 or 9999).

* Standard Port Scan:

nmap -p 23,2323,9999 <target-ip>

* Full Port Scan (All 65,535 ports):

nmap -p- --open <target-ip>


## Step 2: Grab the Service Version and Banner
Identify the specific software version and operating system. Banners often leak crucial details like the OS version (e.g., Ubuntu, Cisco IOS) or hardware models.

* Automated Version Scan (Nmap):

nmap -sV -p 23 <target-ip>

* Manual Connection (Netcat / Telnet):

nc -vn <target-ip> 23# OR
telnet <target-ip> 23


## Step 3: Run Targeted Nmap NSE Scripts
Use specialized Nmap Scripting Engine (NSE) scripts to probe the service for deeper configuration details:

* Check for Encryption Support:

nmap -p 23 --script telnet-encryption <target-ip>

* Extract Windows NTLM Info: Pulls internal domain names and hostnames from legacy Windows Telnet servers.

nmap -p 23 --script telnet-ntlm-info <target-ip>

## 2. Telnet Exploitation Attack Vectors
Exploiting a Telnet service typically relies on three main vectors: cleartext credential sniffing, weak/default credentials, and legacy software vulnerabilities.
## Attack Vector 1: Cleartext Credential Sniffing (MitM)
Because Telnet does not use encryption, all traffic—including usernames and passwords—travels across the network in plain text.

* Mechanism: An analyst or attacker captures network traffic on the local network using tools like Wireshark or tcpdump.
* Impact: By filtering for Telnet traffic (tcp.port == 23) and selecting Follow TCP Stream, the raw login credentials can be read directly.

## Attack Vector 2: Default or Weak Credentials (Brute-Forcing)
Telnet is frequently found on older embedded hardware, legacy routers, and IoT devices that ship with factory-default login pairs (e.g., admin:admin, root:root).

* Mechanism: Using automated tools to rapidly test lists of common credentials against the open port.
* Execution Example (Hydra):

hydra -L usernames.txt -P passwords.txt <target-ip> telnet


## Attack Vector 3: Software Vulnerabilities
Legacy Telnet daemons (such as old versions of telnetd or legacy Cisco daemons) often contain critical software bugs like buffer overflows.

* Mechanism: Cross-referencing the version discovered during enumeration with public vulnerability databases (e.g., Exploit-DB, CVE catalog).
* Impact: If a known flaw exists, exploitation frameworks (like Metasploit) can execute arbitrary code to grant unauthorized administrative command-line access.

------------------------------
## 3. Remediation & Hardening Strategies

* Replace with SSH: Disable the Telnet service entirely and deploy SSH (Secure Shell) on port 22. SSH encrypts all session traffic, neutralizing packet-sniffing attacks.
* Network Segmentation: If Telnet is strictly required for legacy compatibility, isolate the host within a dedicated, firewalled Virtual LAN (VLAN) with no external internet ingress or egress.
* Credential Hygiene: Ensure factory-default credentials are changed immediately to strong, complex alternatives.
