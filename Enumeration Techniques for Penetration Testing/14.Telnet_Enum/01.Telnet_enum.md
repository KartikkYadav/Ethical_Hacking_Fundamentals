Telnet service enumeration is the process of scanning, identifying, and interacting with an open Telnet port (typically Port 23) to gather system banners, software versions, and configuration details. [1, 2] 
## Scanning and Detection

* Port Discovery: Scan for open ports using network tools like Nmap. Telnet usually runs on port 23, but can be on custom ports like 2323 or 9999. [2, 3] 
* Service Version Scan: Run nmap -sV -p 23 <target-ip> to detect the exact service and application version running behind the port. [3, 4] 
* Nmap NSE Scripts: Use specialized Nmap scripting engine options to extract further details or test specific features:
* telnet-encryption to check if encryption is supported.
   * telnet-ntlm-info to pull NTLM details from Microsoft Telnet services. [1, 2] 

## Banner Grabbing and Interaction

* Manual Connection: Connect directly to the target via command line using telnet <target-ip> <port> to read the welcome banner.
* Information Leakage: Banners often reveal the operating system, device model (such as Cisco or Siemens), and internal hostnames. [2, 5, 6] 

## Security Risks

* Cleartext Transmission: Telnet transmits all data—including usernames and passwords—in plain text, making it vulnerable to packet sniffing.
* Brute-Forcing: Many legacy implementations lack account lockout options, making credential testing straightforward. [2, 4, 6]

To perform Telnet service enumeration, follow these step-by-step methodologies to safely detect, banner grab, and check for misconfigurations on a target system.
## Step 1: Discover Open Telnet Ports
The first step is to check if the target has a Telnet service active. While Telnet typically runs on port 23, administrators sometimes move it to non-standard ports (like 2323 or 9999) to hide it.
Run a standard Nmap port scan:

nmap -p 23,2323,9999 <target-ip>

To scan all 65,535 ports for Telnet if it's hidden:

nmap -p- --open <target-ip>

## Step 2: Grab the Service Version and Banner
Once you find an open port, identify the specific software version and operating system. Banners often leak crucial details like the OS version (e.g., Ubuntu, Cisco IOS) or hardware models.
Option A: Automated via Nmap

nmap -sV -p 23 <target-ip>

Option B: Manual Connection
Connect directly using the standard netcat (nc) or telnet utility to view the raw welcome banner:

nc -vn <target-ip> 23# OR
telnet <target-ip> 23

## Step 3: Run Targeted Nmap NSE Scripts
Nmap features built-in NSE (Nmap Scripting Engine) scripts specifically designed to probe Telnet services for vulnerabilities and configuration details.

* Check for Encryption Support: Determine if the server enforces encryption (rare for Telnet) or allows cleartext.

nmap -p 23 --script telnet-encryption <target-ip>

* Extract Windows NTLM Info: If it's a legacy Windows Telnet server, this pulls internal domain names and hostnames.

nmap -p 23 --script telnet-ntlm-info <target-ip>


## Step 4: Check for Default or Weak Credentials
Many legacy systems or IoT devices running Telnet utilize factory-default credentials (e.g., admin:admin, root:root).
You can use automated tools like Hydra to test a small list of common default credentials:

hydra -L usernames.txt -P passwords.txt <target-ip> telnet

Note: Keep brute-force attempts minimal to prevent account lockouts or system disruptions.
## Step 5: Sniff Traffic (If on a Local Network)
Because Telnet does not encrypt data, all traffic—including usernames and passwords—is sent across the network in cleartext. If you are conducting an authorized man-in-the-middle or local network test:

   1. Open Wireshark or run tcpdump.
   2. Filter the traffic using tcp.port == 23.
   3. Right-click a packet and select Follow -> TCP Stream to view the full plaintext login session.
