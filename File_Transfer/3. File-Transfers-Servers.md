# File Transfer Servers

This section covers modern methods of file transfer using various server protocols, essential for remote administration, penetration testing, secure sharing, and automation in diverse environments.

## Shared directory setup

Follow these steps to create a shared directory accessible for uploads/downloads:

### 1. Create the shared directory:

```bash
cd /opt
```

```bash
mkdir /opt/share
```

### 2. Set permissions:

```bash
chmod 777 /opt/share
```

```bash
chown nobody:nogroup /opt/share
```

```bash
ls -lh /opt | grep share
```

## HTTP / HTTPs server

* **HTTP** typically uses port `80`, **HTTPS** uses `443`. Other common ports: `8080`, `8000`, `8888`.
* For public/automated downloads, always prefer use of **HTTPS** for encrypted, secure transfers.

### setup on debian-based systems

#### 1. Install Apache HTTP Server:

```bash
apt update
```

```bash
apt install apache2
```

#### 2. Start and enable the service:

```bash
systemctl start apache2
```

```bash
systemctl enable apache2
```

#### 3. Check HTTP traffic:

```bash
ss -tulnp | grep :80
```

#### 4. Access from browser:

```text
http://<server_ip>:80
```

* Consider editing `/etc/apache2/apache2.conf` or other site configs for advanced settings.
* For performance and reverse proxy scenarios, `nginx` can be used as a reverse proxy in front of Apache.
* Keep Apache updated for latest security patches, as recent 2025 updates address serious CVEs including SSRF and DoS.

## FTP Server

* **FTP** uses ports `21` (control) and `20` (data); **FTPS** adds encryption via TLS and is strongly recommended over raw FTP.

### ftp setup (debian-based)

#### 1. Install vsftpd:

```bash
apt install vsftpd
```

#### 2. Edit configuration:

* Recommended settings for security and functionality in `/etc/vsftpd.conf`:

```ini
listen=NO
listen_ipv6=YES
anonymous_enable=NO
local_enable=YES
write_enable=YES
chroot_local_user=YES
allow_writeable_chroot=YES
pasv_min_port=10000
pasv_max_port=10100
ssl_enable=YES
allow_anon_ssl=NO
force_local_data_ssl=YES
force_local_logins_ssl=YES
ssl_ciphers=HIGH
ssl_tlsv1=YES
ssl_sslv2=NO
ssl_sslv3=NO
rsa_cert_file=/etc/ssl/certs/vsftpd.pem
rsa_private_key_file=/etc/ssl/private/vsftpd.key
```

#### 3. Restart FTP service:

```bash
systemctl restart vsftpd
```

> For improved security, use **SFTP** instead of FTP where possible.

## SFTP Server

* **SFTP (SSH File Transfer Protocol)** encrypts commands and data for secure transfers.
* Default port: `22`.

### setup on debian (if not already enabled)

#### 1. Ensure OpenSSH is installed:

```bash
apt install openssh-server
```

#### 2. Transfer files with:

* Supports SSH keys, fine-grained permissions, end-to-end encryption, automation, and resumable transfers.

```bash
sftp <user>@<server_ip>
```

## SMB Server

* **SMB (Server Message Block)** protocol supports LAN file sharing across Windows, Linux (via Samba), macOS.

### smb server setup

#### 1. Install Samba:

```bash
apt install samba
```

#### 2. Edit `/etc/samba/smb.conf` to include a share (example):

```ini
writable = yes
guest ok = yes
guest only = yes
read only = no
create mask = 0777
directory mask = 0777
force user = nobody
```

### 3. Set directory permissions for security (recommended):

```bash
chmod 2770 /opt/share
```

```bash
chown nobody:nogroup /opt/share
```

### 4. Restart services:

```bash
systemctl restart smbd.service
```

```bash
systemctl restart nmbd.service
```

> It is better to restrict guest access in production environments; configure users and groups for controlled access.

## TFTP Server

* **TFTP (Trivial File Transfer Protocol)** is fast but insecure; suitable for embedded or firmware configurations only.
* Default port: `69`.

### tftp server setup (debian)

#### 1. Install tftpd-hpa:

```bash
apt install -y tftpd-hpa
```

#### 2. Edit config:

* To allow creation of new files as needed (optional, less secure):

```bash
vim /etc/default/tftpd-hpa
```

* Modify `TFTP_OPTIONS` to include `--create` for upload capability:

```bash
TFTP_OPTIONS="--secure -c"
```

* Set root directory for file serving inside this config.

#### 3. Restart TFTP service:

```bash
systemctl restart tftpd-hpa
```

* Make sure file permissions and ownership are set to allow TFTP writes, usually user `tftp`.

## Popular Client Tools

* **FileZilla:** Free, multi-platform, supports FTP, SFTP, FTPS.
* **Cyberduck:** Cross-platform, supports SFTP/FTP/WebDAV/cloud, automation features.
* **WinSCP:** Windows-only, supports SFTP, SCP, FTP with scripting.
* **Transmit 5:** Advanced Mac client supporting cloud and traditional protocols.

## Security Best Practices

* Prefer encrypted protocols: **SFTP, FTPS, HTTPS** for sensitive transfers.
* Use strong authentication methods, ideally SSH keys instead of passwords.
* Restrict access to shares with proper permissions and groups.
* Regularly audit transfer logs for suspicious activity.
* Keep server and client software updated to patch vulnerabilities.
* Implement multi-factor authentication where possible.
* Schedule regular security reviews and user training to maintain awareness.
